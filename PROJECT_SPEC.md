# Project Constellation — Repo_Dex build mandate

The user-supplied full specification is contained in the downloadable local project archive. This repository's public browser prototype implements only its initial observatory and exploration layer.

## Product thesis

Repositories can act as a portfolio of mechanisms, design lessons, abandoned experiments, and emerging combinations. The goal is to find source-backed cross-project opportunities, rather than generic code-quality tips or arbitrary pairings.

## Required future architecture

- Repository records with visibility, commit identity, access scope, and indexing checkpoint.
- Immutable snapshots with source hashes, file paths, symbols, dates, and parser version.
- Capability genome records: purpose, mechanism, interface, operational/evidence status, constraints, transferability, limitations, beneficiaries.
- Need, relationship, opportunity, experiment, decision, and scan-run tables.
- SQLite as the initial durable store; embeddings only if measured discovery quality justifies them.
- Read-only source inspection with strict exclusion of secrets and all private code from the Pages bundle.

## Evidence ladder

1. Described: project text makes a claim.
2. Located: implementation is located in source.
3. Exercised: relevant test/example is observed.
4. Verified: controlled test establishes behavior.
5. Transferred: an integration experiment validates reuse.

A higher level must never be implied by the lower level.

## Seven engines

Reuse Detective; Missing-Piece Matcher; Archaeologist; Cross-Domain Translator; Invention Laboratory; Leverage Cartographer; Skeptical Challenger.

## Design principles

- The best discovery is specific, traceable, falsifiable, and useful to a named beneficiary.
- Keep a skeptical rejection lane and avoid forced consolidation.
- Track rejected/shelved decisions and resurface only upon material evidence changes.
- A public dashboard must never contain private repository source or secrets.
- No autonomous code edits, merges, pushes, or deployments into analyzed repositories.
- The user approves all consequential mutations separately.

## Initial milestone

Demonstrate at least one manually reviewed, source-grounded, potentially useful connection among 5–10 accessible repositories. Do not claim the full concept exists until that test passes.
